概念详解Skill（技能）

一句话摘要：Skill 是把"完成某类任务的方法论"写成结构化文档（如 SKILL.md），存放在约定目录里，让 AI 助手在遇到相关任务时自动加载并照着执行——本质上是给 AI 装上可复用的"操作手册"。

定义

Skill 是一种"知识打包"机制：将某个任务的最佳实践——触发条件、工作步骤、输出规范、注意事项——写成一份带元数据（name、description）的说明文档，放在 AI 助手约定的技能目录（如 .workbuddy/skills/）下。当用户的请求匹配技能描述时，助手会先读取这份文档，再按其中的流程执行，从而稳定地复现高质量的工作方式。

SKILL.md 的典型结构

---
name: my-skill          # 技能名称
description: 何时触发、做什么  # 助手据此判断是否加载
---
# 技能标题
## 目的 / 触发条件        # 什么时候用
## 工作流程               # 分步骤怎么做
## 输出规范               # 产物的格式与质量要求
## 边界                   # 不做什么

生活化类比

💭 类比：Skill 就像交给新员工的SOP 手册（标准作业程序）。没有手册时，新员工每次做事全凭临场发挥、质量忽高忽低；有了手册，"财务报销""周报撰写"都按固定流程执行，谁来做得都一样好。

例子

📝 例子：本仓库的 concept-learning-materials 技能就是一例：它规定"当用户要学习某概念时，按四步生成 4 个互相链接的 HTML 页面"。以后你只需说"帮我搞懂 Transformer"，助手就会按既定规范产出统一格式的学习资料——这就是技能带来的确定性和复用性。

常见误区

⚠️ 误区一：Skill 等于提示词。提示词是单次对话的临时指令；Skill 是持久化、可版本管理、可分享的方法论资产。
⚠️ 误区二：写得越多越好。技能文档应精炼、可执行——模糊冗长的描述反而让助手无所适从。

学习目标

  • 能说出 SKILL.md 必备的 YAML 元数据字段（name、description）及其作用
  • 能把一个重复性任务整理成一份可复用的技能文档
  • 能解释 Skill 与单次提示词的两点本质区别

核心问题

  • 助手是靠什么判断"该加载哪个技能"的？（提示：description 与用户请求的匹配）
  • 什么样的任务最值得沉淀为 Skill？

使用边界

Skill 适合沉淀流程明确、可复用、对格式/质量有要求的任务；一次性、高度即兴的任务写成 Skill 反而是负担。技能不是执行保证——助手仍可能偏离文档，重要产出需要人工抽查。

自测问题

  1. SKILL.md 顶部的 YAML 中，助手用来判断"何时触发"的字段是哪个？（提示：description）
  2. 如果把技能描述写成"帮我做事"，会发生什么？（提示：无法判断何时触发，技能形同虚设）
  3. 为什么说 Skill 应放在项目级 .workbuddy/skills/ 目录并提交到仓库？（提示：可版本管理、可分享、跨设备复用）
